Context and memory in an agent

Quick reference for Lesson 1, Objective O3.

Definitions

  • Context window: all the text one model call can reference — system prompt, tool definitions, prior messages and tool results, and the output. Not the model's training data.
  • Token: the small chunk of text (close to a word-piece) a model reads or writes one at a time; what the window's size and a request's cost are measured in.
  • Context rot: accuracy and recall degrading as token count grows, even within a model's limit, because it must weigh far more token relationships.
  • Retrieval (just-in-time loading): keeping a pointer to a large, stable source and pulling in only the relevant slice on demand.
  • Notes as memory (structured note-taking): the agent writes a fact it learned to storage outside the context window, so a later session can read it back.

What counts toward the context window

  • The system prompt / instructions
  • Every tool's schema (definition), whether or not it gets called this turn
  • Every prior message, including tool results, images and documents
  • The output the model generates this call, including any thinking

All of it is resent, and billed, on every later call in the same session — a bigger window raises the ceiling, it does not lower the cost or protect accuracy.

Within a session vs. between sessions

Within one sessionBetween separate sessions
Default behaviorEverything accumulates; nothing is dropped automaticallyResets completely; a new session starts empty
What the model seesSystem prompt + tools + all prior turns this runOnly what the harness deliberately puts in
How a fact survivesAutomatically, by staying in the growing historyOnly if written to storage outside context and read back
Rule of thumb: if a fact only exists as chat text and must be true next session, something has to write it down before the session ends. Nothing crosses the session boundary on its own.
