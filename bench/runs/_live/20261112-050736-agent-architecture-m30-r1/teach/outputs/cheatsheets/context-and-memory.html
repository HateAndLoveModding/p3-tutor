Context and memory in an agent

From Lesson 1.

Rules

  • The model sees only the current request: system prompt, all messages, tool results, tool definitions.
  • The program resends the full history on every call. Input tokens per request = the sum of every call's whole input.
  • Nothing carries to a new session unless you save and reload it.
  • Bigger window means more fits, not better. Context rot lowers recall as tokens grow.

Where does it go?

InformationPlace
Rules, tool descriptions, needed every callSystem prompt (context)
Exact facts: training status, bookingsDatabase record, read by a tool or loaded by the program
Soft facts: preferencesModel-written notes (memory tool), loaded at session start
Large documents: manualsSearchable store behind a search_manuals tool
Stale tool resultsClear them; compact only long conversations

Retrieval

  • Chunk, then index (embeddings for meaning, BM25 for exact strings), then return the top few chunks.
  • Embeddings miss exact codes; BM25 misses paraphrases; a hybrid covers both.
  • If the right chunk is not retrieved, the model never sees it.
