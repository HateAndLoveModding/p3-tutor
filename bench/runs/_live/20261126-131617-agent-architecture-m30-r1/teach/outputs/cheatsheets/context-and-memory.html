Context and memory: which one do I need?

From Lesson 1, Objective O3. Use this when designing what the makerspace assistant keeps, saves, or looks up.

The one rule: nothing survives a call, a session, or a document's length unless something explicitly resends it, writes it, or searches for it. There is no automatic memory.
MechanismWhat it holdsHow it persistsWhen to use it
Context window System prompt, conversation so far, all tool results in this run Resent in full on every model call, within one run; never trimmed automatically It's always present; the design question is what to keep out of it
Within-session "memory" Earlier turns in the same open chat Same as context window: the whole transcript is resent each turn No action needed; this is automatic within one open session
Between-session memory A fact that must be true in a future session (e.g. a certification) Explicit write to storage at session end, explicit read at next session's start Any fact about ongoing state that outlives one visit: training, bookings, preferences
Retrieval Chunks of a large, mostly fixed document set (manuals, procedures) Documents are indexed once; a search at question time injects only the matching chunk The source is a document that already exists in full and is too big to paste in whole
Notes Short, specific facts produced by the system itself as things happen Written when learned, reloaded only when relevant, kept small and curated The information is not a pre-existing document, it's a fact about an event or state
Quick test: "Does this already exist as text somewhere long?" → retrieval. "Did this just happen and must be true later?" → a note. "Is it already in this run's history?" → it's already in context, no action needed. "Did the session just end?" → it's gone unless you wrote it down.
